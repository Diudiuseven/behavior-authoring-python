# 行为定义编写与版本化发布

本服务管理行为图（Behavior Graph）的完整生命周期：**草稿编辑 → 成组校验 → 原子发布 →
不可变版本 → 运行时按版本读取**。本文档说明版本语义与发布流程。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 草稿（Draft） | 可反复修改的工作副本，携带单调递增的 `revision` 作为乐观并发令牌 |
| 发布版本（Published Version） | 草稿校验通过后生成的**不可变**快照，版本号从 1 单调递增 |
| 快照（Snapshot） | 发布时刻图的规范化 JSON，是读取的唯一事实来源，发布后绝不修改 |
| 内容哈希（Content Hash） | 图规范化形式（与节点/连线列出顺序无关）的 SHA-256，作为编译缓存键 |
| Schema 版本 | 图结构的版本号（当前为 2），用于跨版本结构演进与迁移 |

## 版本语义

1. **不可变性**：已发布版本的快照永不修改、永不删除。回滚只是给版本打
   `rolled_back` 标记，快照原样保留，仍可按版本号精确读取。
2. **可复现读取**：`GET /graphs/{id}/versions/{n}` 永远返回发布时刻的定义；
   旧 schema 版本的快照在读取时于内存中迁移到当前结构，**存储内容不变**。
3. **多版本共存**：同一图的所有发布版本长期共存，运行时按指定版本读取；
   `GET /graphs/{id}/latest` 返回最新的未回滚版本。
4. **原子发布**：发布按 权限检查 → 成组校验 → 编译 → 单次原子提交 的顺序执行。
   任一步骤失败都不会产生半个版本，消费者在发布完成前只能读到上一个完整版本。

## 发布流程

```
设计者                    服务
  |  PUT /graphs/{id}/draft (base_revision=N)      |
  |----------------------------------------------->| 乐观并发 CAS：revision 不匹配返回 409
  |  POST /graphs/{id}/draft/validate              | 及冲突详情（当前 revision、最后修改者）
  |----------------------------------------------->| 返回逐条定位到元素的校验报告
  |  POST /graphs/{id}/publish                     |
  |----------------------------------------------->| 校验失败 → 422 + 全部问题定位；
  |                                                 | 校验通过 → 原子提交新版本（201）
运行时
  |  GET /graphs/{id}/versions/{n}  或  /latest    |
  |----------------------------------------------->| 不可变快照（必要时内存中迁移旧结构）
  |  GET /graphs/{id}/versions/{n}/plan            |
  |----------------------------------------------->| 编译产物，按内容哈希缓存复用
```

## 校验规则（成组执行，逐条定位）

校验失败不会只返回笼统错误，每个问题都包含 `code`（机器可读）、`message`（原因）、
`element_kind` / `element_id` / `field`（定位到具体节点、连线、黑板键或参数路径）：

- **节点组**：id 唯一非空；叶子节点（action/condition）不得有子节点；decorator 至多一个子节点。
- **连线组**：id 唯一；source/target 必须指向存在的节点；禁止自环；guard 表达式引用的黑板键必须已声明。
- **黑板组**：键名为合法标识符且唯一；默认值类型匹配；required 键无默认值时给出警告。
- **参数引用组**：节点参数中所有 `{"key": "..."}` 引用必须指向已声明的黑板键（支持嵌套路径定位）。
- **图级**：entry_node 必须存在（或可唯一推断）；所有节点可达；无环。

## 并发编辑

草稿保存采用乐观并发：保存时必须携带读取时的 `base_revision`，仅当其等于当前
revision 才成功。冲突方收到 409 及可解释信息（期望 revision、当前 revision、
最后修改者），重新加载后可基于新 revision 重试，**不会静默覆盖他人修改**。

## 结构演进与迁移

- 每个快照记录发布时的 `schema_version`。
- 读取时按迁移链逐版本升级（当前实现了 v1 → v2：节点 `type`→`kind`、连线补 id、
  黑板映射→键对象、`"@key"` 参数引用→`{"key": key}`）。
- 迁移只发生在内存中，**绝不改写已发布快照**。
- 无法迁移时（缺 schema_version、版本过新、无迁移路径）抛出带明确原因的
  `MigrationError`。

## 权限与审计

| 角色 | save_draft | publish | rollback |
| --- | --- | --- | --- |
| editor | ✓ | ✗ | ✗ |
| publisher | ✓ | ✓ | ✗ |
| admin | ✓ | ✓ | ✓ |

每次权限判定（无论放行或拒绝）都会写入审计日志（操作者、动作、图 id、是否放行、
原因、时间戳），越权发布/回滚被拒绝且可通过 `GET /audit` 追溯。

## 编译缓存

编译是图规范化形式的纯函数，结果按内容哈希缓存：定义未变时直接复用缓存；
同一定义（即使节点/连线列出顺序不同）哈希相同，重复编译结果完全一致。
